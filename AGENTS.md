# Driverade — Developer/AI Project Context

Before **every** Driverade code generation, edit, review, merge or release decision:
1. Read [docs/NEXT_SESSION_CHECKPOINT.md](docs/NEXT_SESSION_CHECKPOINT.md), the applicable feature contract, and [docs/BRAINSTORMING_PROTOCOL.md](docs/BRAINSTORMING_PROTOCOL.md).
2. Verify the **live** repo branch, active PRs, diagnostic evidence, signed APK identity, and owner-device test status; never equate passing CI with reliable live parser/alerts.
3. Preserve the privacy-first offline workflow and validated acquisition → parser → gates → alerter path. Keep Driverade separate from Personal Assistant and cryptographic-engine.
4. When a design decision changes, or conversation focus leaves architecture, **write its dated, status-labeled delta to this project's notes before moving on**. Confirm actual saved links; never say it was saved if the write failed. Treat speculative plans as proposals.
5. For code changes, state the relevant roadmap decision and how the edit conforms; if it conflicts, document the new owner-approved choice before applying it.

This is a project-documentation convention, not a guarantee of automatic background execution or that every model/chat has GitHub access.
